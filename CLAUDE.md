# Global Recall

A daily-practice geography app that turns adults who feel mild shame about their geography knowledge into people who can actually name every country on Earth — using a 3D globe as a visual memory palace.

**Stage:** Live PWA at `globalrecall.themillrace.ca`. Pre-App-Store launch.
**Distribution:** Apple App Store + Google Play via Capacitor wrap (publisher: Millrace Inc., Canadian corp). DUNS submitted, Apple Developer Program enrollment pending. Bundle ID locked: `com.millrace.globalrecall`.
**Motivation:** Incidental income / studio side-project. Realistic target $300–$2K/mo within 6–12 months; stretch path ~$5K/mo if Daily mode catches.

## Stack

- **Frontend:** Single `play.html` (the game), vanilla JS, no framework, no build step. `index.html` is the public splash/landing page — static, no game code, no MapLibre.
- **Map rendering:** MapLibre GL JS 5.6.0 from unpkg CDN. Native `projection: 'globe'`, with a flat Mercator toggle (the Render Mode switch) for weak devices. Replaced globe.gl/Three.js in the FT-008 migration — `docs/maplibre-migration-plan.md` is the durable record of why and how.
- **Backend:** None. Pure client-side game. No accounts, no sync.
- **Persistence:** `localStorage`, wrapped behind `src/storage.js` (mirrored inline in `play.html`). Schema v3 with migration runner.
- **Hosting:** Vercel, auto-deploys from `main`. Service worker (`sw.js`) for offline + cache invalidation.
- **Domains:** `globalrecall.app` is canonical (registered at Cloudflare; Cloudflare is DNS-only, grey-cloud, pointing at Vercel). `globalrecall.themillrace.ca` still resolves and is the origin the native shells call for `/api/leaderboard`.
- **Routing:** `/` serves the splash, `/play` rewrites to `/play.html` (the game). Vercel checks the filesystem *before* rewrites, which is why the game is not named `index.html` — a rewrite off `/` would never fire.
- **Tests:** Vitest. ES modules in `src/` for testable helpers, mirrored inline in `play.html` (no build step).
- **App-store wrapper:** Capacitor. Scaffolded in `ios/` + `android/` (bundle `com.millrace.globalrecall`). `www/` is a gitignored copy generated by `npm run cap:copy` — `play.html`/`sw.js`/`manifest.json` stay the single source of truth (`cap:copy` lands `play.html` at `www/index.html`, so the native shells boot straight into the game and never see the splash). Run `npm run cap:sync` after editing them to refresh both native projects. Submission to TestFlight / Play internal track is still pending (needs Apple Developer Program enrollment + Google Play Console account).
- **Analytics:** None yet. v1: UTM tags + App Store Connect / Google Play Console install/retention. v1.1: Plausible (~$9/mo) when event-level data is wanted.

Don't suggest switching the rendering library, backend posture, auth posture, or hosting without being asked — those are settled. Specifically don't suggest TypeScript migration, moving to Firebase / Supabase / any database, or adding a framework (React, Vue, Svelte). Splitting code across more files, introducing a build step, or restructuring the project layout are open conversations — propose them when there's a concrete benefit, but always as a "want me to do this?" question, not unilaterally.

## Architecture

### Data model (per-device, localStorage)

All keys under the `gr_` prefix. Read/write only through the `Storage` module — never direct `localStorage` calls in feature code.

- `gr_schema_version` — integer. Migration runner walks v0 → SCHEMA_VERSION on every boot.
- `gr_ghost` — Name All replay blob (`{ countries, timestamps, totalTime }`).
- `gr_recs` — per-mode records (`{ name_all: { best, best_time, runs } }`).
- `gr_sprint_best` — integer.
- `gr_daily` — `{ lastDay, streak, longestStreak, lastScore, lastTotal }`.
- `gr_style` — selected globe style.
- `gr_install_dismissed` — PWA install-banner snooze timestamp.
- `gr_lite_mode` — boolean | null. null = auto-detect on first boot.

### Key flows

**Identify, not recall, is the product goal.** Knowing *where* a country is matters more than being able to rattle off names. Daily, Sprint and Strict are all identify modes and share one engine: highlight a country, fly the camera to it, ask for its name. Keep them consistent — a change to how identify feels should land in all three.

- **Daily mode** is the retention engine. 10 date-seeded countries per UTC day, one at a time. Streak increments on consecutive plays, resets on any gap, once-per-day idempotent.
- **Sprint** is a 1-minute countdown for fluency drilling. Leaderboard-eligible.
- **Strict** is all 195 on sight, three strikes. Leaderboard-eligible.
- **Name All** is the flex/trophy layer and the one recall mode — 195 countries from memory, no prompts, no order. Ghost replay lets you race a prior run.
- **Easy Mode** (multiple-choice with continent hint) is onboarding for kids / brand-new users, not a peer mode to the above.

### Architectural decisions (locked — do not revisit mid-build)

- **Per-device storage for personal records.** No accounts, no auth, no cloud sync of streaks / ghosts / PBs. All "streak" / "longest" / "records" are per-device.
- **Arcade-cabinet leaderboard, local-first with opportunistic global sync.** Local top-100 board per mode (Sprint, Strict) with 3-letter initials in `gr_leaderboard`. Local is the player's truth and always works offline. On `submitInitials`, the client fires a best-effort `POST /api/leaderboard` to sync to a Vercel function backed by Upstash Redis. Server stores only `{initials, score, mode, ts}` — zero PII. Local board renders if the global fetch fails ("GLOBAL BOARD UNAVAILABLE · OFFLINE?"). 30s client-side cache on global reads. Server validates score range + initials shape; no rate limit (locked simplest posture — board is wipeable with `redis.del('lb:<mode>')` if it ever gets bad). Deliberate deviation from the prior "no leaderboard" decision.
- **Storage abstraction is the migration path.** The day cloud sync becomes a real ask, only `src/storage.js` + its inline mirror change. Every feature reads/writes through it.
- **Schema versioning is load-bearing.** Returning users must walk through every migration cleanly. Never rewrite an existing migration; only add new ones.
- **Daily seeding depends on stable country order + launch date constant** (`Date.UTC(2026, 4, 12)` in `getDailyNumber`). Changing either breaks streaks for existing users.
- **The country list is 200, not 195, and the map decides what belongs.** The UN-195 convention plus Taiwan, Kosovo, Western Sahara, Somaliland and Northern Cyprus. The stance: the game teaches awareness of the globe, contested territories are where that matters most, politics is not an input, so the bias is toward more granular — but we don't adjudicate sovereignty ourselves. The rule is **drawn as its own feature in Natural Earth `admin_0_countries`, with itself as `SOVEREIGNT`**. That delegates the call to cartographers who did it in public, and it means a place the globe can't paint is out by construction. Antarctica is the one carve-out (no population, no government); Palestine is the one inclusion the rule misses (Natural Earth files it under Israeli sovereignty) and comes in via the 195. `docs/country-list.md` is the public record. `MAX_SCORE` in `api/leaderboard.js` and `TOTAL` track the real count; any `195` in the UI is a stale label.
- **Country aliases are tuned for typo tolerance.** The `RAW` array + alias lists in `play.html` are mature (`src/core.test.js` covers the matching). Adding aliases is fine; restructuring the matching engine requires care.
- **Publisher = Millrace Inc., bundle = `com.millrace.globalrecall`.** One-shot at first store submission. Don't change.
- **Monetization is open, but deferred.** This was previously locked out entirely; the owner has since reopened it. Anything paid must be opt-in and off by default, and nothing gets built until daily retention is proven. The intended wedge is free async racing as growth, with money reserved for features that genuinely cost to scale (live realtime races, cloud save, private friend boards). Don't scaffold billing before then.

### Current code organization (historical, not religious)

The game lives in a single `play.html` with testable helpers in `src/*.js` mirrored inline. This is **how the project currently is**, not a rule. The owner prefers a tidy codebase and is open to splitting things out (more files, a build step, normal ES module imports without the inline mirror duplication) when it serves a concrete benefit. If you see code that would clearly be cleaner if extracted, propose it as a "want me to do this?" question with a one-line benefit — don't just refactor unilaterally, and don't religiously preserve the single-file pattern either.

Key conventions:
- Testable code currently goes in `src/*.js` as ES modules and is mirrored inline in `play.html` (search for "Mirror of src/" comments). When you edit one, you edit both. This duplication exists because there's no build step yet — it's not a virtue, just current reality. If you want to propose a build step that eliminates it, that's a fine conversation.
- Service worker cache name must bump on every shipped change or users get stale code. Pattern: `global-recall-vN`.

## Conventions

- **Don't sound like an AI wrote it.** This applies to code comments, commit messages, and conversational replies. The tells to avoid: excessive enthusiasm ("Great question!", "Absolutely!"), restating the user's question before answering, hedging everywhere ("might potentially..."), bullet vomit when prose would be clearer, decorative emojis used as visual flair, closing pleasantries ("Let me know if you have any other questions!"). The owner DOES use emojis in conversation — that's fine and not the point. The point is voice: sound like a builder explaining their work to another builder, not like a polished documentation deliverable.
- **Commit messages: tight headline, context paragraph(s) explaining WHY.** Look at recent commits for the voice. No emoji in commit text. No marketing tone.
- **Co-author trailer on all AI-assisted commits:** `Co-Authored-By: Claude Opus 4.7 <noreply@anthropic.com>`.
- **UI copy emojis are deliberate** (🔥 ⊕ ◎ 📅 🌃 ⚡ etc.) — part of the brutalist visual language. Keep them where they exist; add new ones only as deliberate UI choices, not as decoration.
- **Service worker cache version bumps on every shipped change.** Otherwise users get stale code.
- **No analytics / telemetry libraries** until the v1.1 Plausible step in the stack decision.
- **No stray `console.log`** in shipped code. `console.error` for genuine error paths is fine.
